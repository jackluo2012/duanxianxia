# 短线侠系统部署方案设计

**设计日期:** 2025-01-13
**设计目标:** 为短线侠系统创建健壮的生产部署解决方案

---

## 1. 设计概述

### 1.1 核心需求
- 支持 Docker Compose 部署环境
- 提供一键部署功能
- 支持完全重置到初始状态
- 提供全面的部署文档

### 1.2 技术选型
**方案:** 增强 Shell 脚本方案
**理由:**
- 复用现有脚本,风险最小
- 实施快速,灵活性好
- 易于调试和维护
- Docker Compose + Shell 职责清晰

## 2. 部署模式设计

### 2.1 三种部署模式

#### 快速部署模式 (Quick)
- **用途:** 开发过程中的快速迭代
- **操作:**
  1. 停止运行中的服务
  2. 拉取最新代码(可选)
  3. 重新编译变更的服务
  4. 重启服务
  5. 健康检查
- **特点:** 保留所有数据和配置
- **命令:** `./deploy.sh quick`

#### 完全部署模式 (Full)
- **用途:** 首次部署或需要完全清理时
- **操作:**
  1. 停止所有服务
  2. 清理 Docker 容器和数据卷
  3. 清理编译产物和日志
  4. 重新构建所有服务
  5. 初始化数据库
  6. 启动所有服务
  7. 完整健康检查
- **特点:** 完全清理后重新部署
- **命令:** `./deploy.sh full`

#### 增量更新模式 (Update)
- **用途:** 日常代码更新
- **操作:**
  1. 停止服务
  2. Git pull 最新代码
  3. 增量编译(仅编译变更部分)
  4. 重启服务
  5. 健康检查
- **特点:** 仅更新代码和重新编译
- **命令:** `./deploy.sh update`

## 3. 环境检查机制

### 3.1 必检项(失败则阻止部署)

1. **Docker 环境** - 检查 Docker 是否安装并运行
2. **Docker Compose** - 检查 docker-compose 命令是否可用
3. **Rust 工具链** - 检查 cargo、rustc 版本
4. **端口占用** - 检查关键端口(8080-8085, 6379, 5433, 8123, 9000)
5. **磁盘空间** - 检查可用空间是否 > 5GB
6. **内存空间** - 检查可用内存是否 > 2GB
7. **文件权限** - 检查日志目录、services 目录的写权限

### 3.2 警告项(提示但继续)

1. **Git 状态** - 检查是否有未提交的代码变更
2. **环境变量** - 检查 .env 文件是否存在
3. **网络连接** - 检查能否访问 crates.io

### 3.3 检查脚本
- **文件:** `check-env.sh`
- **独立运行:** `./check-env.sh`
- **自动执行:** 部署前自动运行
- **输出:** 彩色格式化输出,清晰标识 ✅/⚠️/❌

## 4. 错误处理和回滚机制

### 4.1 多层错误处理

#### 第 1 层: 阶段性检查点
每个关键阶段设置检查点:
1. 环境检查后
2. 停止服务后
3. 数据清理后(仅 full 模式)
4. 编译构建后
5. 服务启动后
6. 健康检查后

#### 第 2 层: 备份和快照
部署前自动创建:
- **配置备份:** `backup/config-<timestamp>/`
- **数据库快照:** `backup/db-<timestamp>/`
- **PID 文件备份:** 记录当前运行的进程

#### 第 3 层: 自动回滚
失败时执行:
1. 停止新启动的服务
2. 恢复配置文件
3. 从备份恢复数据(仅 full 模式)
4. 重启之前的服务
5. 生成失败报告

### 4.2 错误日志
- **位置:** `logs/deploy-<timestamp>.log`
- **格式:** 带时间戳的结构化日志
- **内容:** 完整的操作记录和错误堆栈

## 8. 运维建议

### 8.1 日常使用
- 开发环境: 使用 `quick` 模式
- 测试环境: 使用 `update` 模式
- 首次部署: 使用 `full` 模式

### 8.2 备份策略
- 配置文件: 每次部署前自动备份
- 数据库: 每日定时备份

- 端口监听状态

- 日志错误率

## 9. 风险和限制

### 9.1 已知风险
- Rust 编译时间较长(首次约 10-30 分钟)
- 端口冲突需要手动解决
- 数据备份可能占用较大空间

### 9.2 平台限制
- 主要针对 Linux/macOS 优化
- Windows 需要 WSL 或 Git Bash 环境
- Docker 必须预先安装
